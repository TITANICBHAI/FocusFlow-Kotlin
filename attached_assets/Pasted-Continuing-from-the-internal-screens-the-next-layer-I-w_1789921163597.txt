Continuing from the internal screens, the next layer I would fix is the **shared modal / overlay system**.

This matters because these modals appear from multiple internal screens, and right now the Kotlin version repeatedly falls back to `AlertDialog`, `Button`, `OutlinedTextField`, `Checkbox`, and large Material shapes. That makes the entire app feel inconsistent even when the underlying screen is good.

Use the React implementation as the dimensional source of truth here too.

internal fun FocusFlowModalCard(

These are important because they're **not just internal screens**; they are the places where the user repeatedly sees forms, lists, switches, time selectors, app pickers, warnings, and destructive actions.

The pattern from the React source is very consistent:

```text
Modal header      ~15sp
section label     ~11sp
body              ~13sp
field             ~44–48dp
app row            ~40dp icon + 8–12dp padding
checkbox           22dp
button             ~44–48dp
radius             10dp / 16dp
```

So I would **not let the agent independently style those files**.

The next pass should turn that entire defense/launcher modal family into a common component system, otherwise the same oversized Android controls will keep reappearing in another part of the app.
