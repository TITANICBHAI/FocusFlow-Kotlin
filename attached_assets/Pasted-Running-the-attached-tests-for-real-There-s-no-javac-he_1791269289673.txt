## Extra checks I ran on the schedule maths
- **Refactor safety:** the shared window maths matches the original accessibility-service logic on 200,000 random valid windows, with zero differences.
- **One intentional difference:** an end time of 24:00 used to be active and is now treated as invalid. The Kotlin UI clamps to 0–23, so only a hand-edited or imported schedule could carry it.
- **Boundary alarm:** it never missed a transition in UTC, Kolkata or London.
- **DST timezones:** in New York and Sydney it fired up to 60 minutes late when a window edge falls in the skipped or repeated 02:00–03:00 hour. That is two days a year, only for windows with an edge in that hour. Capping the alarm at 60 minutes ahead, so it re-syncs hourly, would fix it.
- **Duplicate logic:** `ForegroundTaskService` (~L1476) still has its own copy of the window maths. It matches the old behaviour, but it isn't using the shared helper.
