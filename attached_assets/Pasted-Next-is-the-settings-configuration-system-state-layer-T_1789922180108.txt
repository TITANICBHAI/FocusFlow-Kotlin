Next is the **settings/configuration + system-state layer**. This is the remaining group that can still make the app feel inconsistent even after the main screens are polished.

I checked the latest Kotlin source and the React counterparts. There are a few particularly important findings:

* `DarkModeToggle.kt` is a **special control** and should **not** use the generic 44×26 FocusFlow switch. React explicitly uses **58×30** with a 24dp knob and light/dark iconography.
* `OverlayAppearanceModal.kt` is still heavily Material-based in Kotlin.
* `DailyAllowanceModal.kt` is currently much larger than its React counterpart.
* `StandaloneBlockSetupScreen.kt` is still using an oversized `TopAppBar` + 20dp padding + large cards.
* `AllowedAppsDialog.kt` is still an `AlertDialog`.
* `BlockedAppOverlay.kt` is a very important user-facing screen and should match the product's enforcement UI rather than looking like a generic error.
* `TimelineView.kt` is still using a stock `Card`.
* `AccessibilityRestrictedRecovery.kt` and `RestrictedSettingsBanner.kt` are functional but visually much heavier than React.
* The error UI should also be brought into the same system.

So this is the next agent pass.
