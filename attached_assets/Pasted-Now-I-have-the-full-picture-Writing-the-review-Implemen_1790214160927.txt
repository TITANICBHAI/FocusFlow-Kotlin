### Issue 1 — Real bug: `focusRequester` will crash when notification opens Stats

**File:** `DayRatingBar.kt`

The `focusRequester` is attached to the note `OutlinedTextField`, which lives inside `AnimatedVisibility(visible = tappedRating != null)`. When the daily notification fires and the user opens Stats with no rating set yet, `AnimatedVisibility` has removed the note field from the composition. Calling `focusRequester.requestFocus()` on a composable not in the composition throws `FocusRequester not initialized`.

**Fix** — move `focusRequester` to the rating row (always in composition):

```kotlin
Row(
    modifier = Modifier
        .fillMaxWidth()
        .horizontalScroll(rememberScrollState())
        .focusRequester(focusRequester),   // ← was on OutlinedTextField
    horizontalArrangement = Arrangement.spacedBy(4.dp),
) {
    (1..10).forEach { ... }
}
```

Remove `.focusRequester(focusRequester)` from the `OutlinedTextField`. The `LaunchedEffect(requestFocus)` stays as-is — it now scrolls and focuses the number row, which is always present.

### Issue 2 — Note text lost when user navigates away without pressing Done

**File:** `DayRatingBar.kt`

The note field only saves on `ImeAction.Done`. If the user types a note and switches tabs or navigates away without pressing Done, the note is discarded.

**Fix** — add a `DisposableEffect` inside the `AnimatedVisibility` block, after the `OutlinedTextField`:

```kotlin
DisposableEffect(Unit) {
    onDispose {
        val r = tappedRating ?: return@onDispose
        if (noteText.isNotBlank()) {
            onSubmit(
                selectedDate, r, contextTag,
                noteText, appTags.toList(), wordTags.toList(),
            )
        }
    }
}
```

This runs when the composable leaves the composition — catching back press, tab switch, and any other navigation away.
