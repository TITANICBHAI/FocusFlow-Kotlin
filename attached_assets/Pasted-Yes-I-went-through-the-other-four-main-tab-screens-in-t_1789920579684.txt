```kotlin

    modifier = Modifier.width(112.dp),
```

Five × 112dp already makes the filter row 560dp before accounting for gaps/borders, which pushes the design toward oversized pill controls.

Use a compact custom horizontal filter instead.

For example:

```kotlin

private fun StatsWindowPill(
    label: String,
    selected: Boolean,
    onClick: () -> Unit,

    Box(
        modifier = Modifier
            .clip(CircleShape)

                else DarkSurfaceVariant

            .padding(
                horizontal = 14.dp,
                vertical = 8.dp,

        contentAlignment = Alignment.Center,
    ) {
        Text(
            label,
            fontSize = 13.sp,
            fontWeight = FontWeight.Bold,
            color = if (selected) Color.White else DarkTextSecondary,
        )
    }
}
```

Then horizontal-scroll those.

# 6. The other major issue: Material `Card`

This is important for **Stats, Settings, Defense, and some secondary screens**.

Anywhere the Kotlin UI currently does:

```kotlin
Card {
    ...
}
```

or:

```kotlin
Surface(
    tonalElevation = ...
)
```

without an explicit reference style, the agent should treat it as suspicious.

The React reference is much flatter.

For the redesigned main screens:

```kotlin
Box(
    Modifier
        .clip(RoundedCornerShape(16.dp))
        .background(DarkCard)
        .border(1.dp, DarkBorder, RoundedCornerShape(16.dp))
)
```

is often a better match than:

```kotlin
Card { ... }
```

because it gives direct control over:

* radius
* border
* elevation
* padding
* background

without Material adding geometry we didn't ask for.
